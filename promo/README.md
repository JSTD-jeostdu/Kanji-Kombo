# 홍보 숏폼 영상

8비트 픽셀 스타일 36초 세로 영상. 앱 데이터와는 별개로, 이 폴더만으로 돌아갑니다.
모든 프레임 오른쪽 위에 `@jungputer` 표기가 들어갑니다 (`HANDLE` 상수).

```bash
python promo/build_promo.py                    # out/칸지콤보_홍보_36초.mp4 (음악 포함)
python promo/build_promo.py --still 6.2        # 6.2초 장면만 PNG로 확인
python promo/build_promo.py --no-audio         # 무음으로
python promo/build_audio.py                    # 음악만 out/promo_audio.wav 로
```

ffmpeg가 PATH에 없으면 `--ffmpeg "C:\...\ffmpeg.exe"` 로 경로를 줍니다.
결과물은 **1080×1920 · 30fps · 36초 · H.264 + AAC** — 쇼츠·릴스·틱톡에 그대로 올라갑니다.

## 장면 구성

컷이 전부 짝수 초에 떨어집니다. 음악이 120BPM이라 한 마디가 2초 — 장면이 바뀔 때마다 박자도 함께 바뀝니다.

| 시간 | 장면 | 하는 일 |
| - | - | - |
| 0~4초 | 훅 | 낱글자가 흩어져 떠다님 · "한 글자씩 외우고 계신가요?" |
| 4~8초 | 콤보 | 毎 + 日 충돌 → `2 HIT COMBO!` · 앱 이름의 시각화 |
| 8~14초 | 학습 카드 | 숙어·읽기·뜻 + 한·일 음훈 병기 |
| 14~20초 | 예문 | 한 글자씩 타이핑되는 예문 + 한국어 해석 |
| 20~26초 | 워크시트 | 열 칸을 한 칸씩 손으로 채움 → "손으로 10번 → 앱으로 복습" |
| 26~30초 | 복습 | 자가평가 버튼 → "다음 복습: 7일 뒤" |
| 30~34초 | 마무리 | 로고 · 한자/숙어/예문 수 · 주소 |
| 34~36초 | 댓글 안내 | "아무 댓글이나 남겨주시면 워크시트를 보내드립니다" |

영상의 주장은 **쓰고(워크시트) → 외우고 → 복습한다(앱)** 한 줄입니다. 워크시트 장면과
복습 장면이 이어 붙어 있는 건 그래서입니다.

## 소리 (`build_audio.py`)

음악도 효과음도 전부 수식으로 만든 8비트 소리입니다. 외부 음원을 쓰지 않으니 저작권
문제가 없고, 영상과 같은 스크립트에서 시간을 계산하므로 박자가 어긋나지 않습니다.

NES의 음원 구성을 그대로 흉내냅니다 — 펄스1(멜로디) · 펄스2(아르페지오) ·
삼각파(베이스) · 노이즈(타악기·효과음).

| 시간 | 소리 |
| - | - |
| 0~4초 | 베이스와 약한 드럼만. 멜로디 없이 비워 둡니다 |
| 4~5.7초 | 노이즈가 올라가며 조여듦 + 스네어 롤 |
| 5.68초 | **충돌** — 화면이 흰색으로 터지는 그 프레임 |
| 5.96 / 6.38초 | 코인 소리 2번 (`2 HIT` · `COMBO!`) |
| 8~20초 | 본 멜로디. 예문 구간은 타이핑 소리가 들리도록 한 단 낮춥니다 |
| 14.4~16.6초 | 글자 수만큼 타이핑 클릭 13번 |
| 20~26초 | 다장조로 잠깐 옮겨 가고, 멜로디가 같은 음을 반복합니다 (쓰는 동작) |
| 21.1~23.5초 | 칸을 채울 때마다 연필 소리 10번 → 23.7초에 완료음 |
| 26.8 / 27.6초 | 버튼 누름 → '7일 뒤' 상승 아르페지오 |
| 30초 | 로고 스탭 + 심벌, 이후 멜로디를 두껍게 |
| 34초 | 마지막 한 방 — 댓글 안내 화면이 뜨는 순간 |

- **음량** — 통합 -13.9 LUFS · 트루피크 -1.1 dBTP. 플랫폼 기준값에 맞춰 둔 것이라
  업로드할 때 다시 손댈 필요가 없습니다.
- **효과음 타이밍** — `effects()` 안에 초 단위로 적혀 있습니다. 장면을 고치면
  이 숫자도 같이 고쳐야 합니다.
- **곡을 바꾸려면** — `LEAD`(멜로디, 한 토큰이 8분음표) · `CHORDS`(마디별 화성) ·
  `play_drums`(패턴). 120BPM이라 한 마디가 2초, 영상의 컷과 1:1로 맞습니다.

## 고치고 싶을 때

- **자막 문구** — 각 `scene_*` 함수 맨 아래 `subtitle(...)`. 길면 글자가 저절로 줄거나 두 줄로 나뉩니다.
- **장면 길이** — `SCENES` 리스트의 프레임 구간(30fps). 컷은 짝수 초에 두는 편이 음악과 맞습니다.
- **수치(120·258·517)** — `STATS`. 데이터를 늘리면 여기도 같이 고쳐야 합니다.
- **댓글 안내 문구** — `scene_comment`. 하트는 `HEART` 비트맵을 찍은 것이라 글꼴을 타지 않습니다.
- **만든 사람 표기** — `HANDLE`. `watermark()`가 흔들림 보정 뒤·주사선 앞에 찍습니다.
  사방 1픽셀 외곽선을 둘러서 흰 플래시 프레임 위에서도 읽힙니다.
- **색** — 팔레트 상수. 앱의 주홍(`#e8503d`)과 종이색을 8비트로 옮긴 값입니다.

## 만든 방식

270×480 픽셀로 그린 뒤 4배 확대(최근접 보간)합니다. 화면 녹화가 아니라 프레임을 직접 찍는 방식이라 픽셀이 뭉개지지 않습니다.

글자는 Yu Gothic(일본어)·Malgun Gothic(한국어)을 작게 렌더링한 뒤 **임계값으로 안티앨리어싱을 잘라내** 픽셀 글꼴처럼 보이게 만든 것입니다. 별도 픽셀 폰트를 받지 않아도 되고, 한자 획이 뭉개지지 않습니다.

중간 프레임 900장은 임시 폴더에 씁니다 — 프로젝트가 OneDrive 안에 있어서 여기에 쓰면 동기화가 돌고 삭제도 막힙니다.
